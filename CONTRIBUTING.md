# Contributing to Upshift

Thanks for helping. Bug reports, fixes, new providers and new playbooks are all welcome.

By taking part you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md). Security issues go through
[SECURITY.md](SECURITY.md), not public issues.

## Set up

You need Python 3.11+, git and [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/harsh-madhav/upshift.git
cd upshift
uv sync
python3 scripts/check_secrets.py --install   # pre-commit hook that blocks committed keys
uv run pytest
```

The tests need no API key and no network model calls. The fix-loop tests drive the real loop (repo, venv,
pytest, git) with a scripted model in place of a real one.

The [Entire CLI](https://docs.entire.io/overview) (`entire plugin install graph`) is optional. Install it if you
work on the graph tools in `upshift/graph.py`.

To try a change end to end, run it on the demo app. `--dry-run` makes no model calls:

```bash
uv run upshift bump --repo demo/shop_app --package pydantic --to 2 --dry-run
```

## Where things live

| Path | What it does |
|---|---|
| `upshift/cli.py` | The `upshift` command and its subcommands |
| `upshift/pipeline.py` | One job end to end: setup → baseline → bump → research → fix → verify → report |
| `upshift/agent.py` | The fix loop: one root cause per round, tests after every round, commit progress, revert regressions |
| `upshift/research.py` | Versions from PyPI, docs and release notes, and a real API diff |
| `upshift/playbook.py` | Turns research into a cited migration playbook, cached in `playbooks/` |
| `upshift/workspace.py` | The target repo's working copy: clone, venv, dependency pins and lockfiles, tests, git checkpoints |
| `upshift/vuln.py` | `scan`: audit with pip-audit (OSV) and pick the smallest fix |
| `upshift/pyversion.py` | `python`: the Python version a repo targets and the files that pin it |
| `upshift/drift.py` | `watch`: find third-party API calls the provider is retiring |
| `upshift/llm.py` | Model providers behind one message format |
| `upshift/graph.py` | Wrappers over the `entire graph` CLI |
| `upshift/tracing.py`, `upshift/neatlogs_mcp.py` | neatlogs tracing and its MCP client |
| `upshift/state.py` | Run state, saved after every step so `resume` works |
| `demo/shop_app/` | The demo app, pinned to old versions on purpose |
| `tests/` | The test suite |

## Common changes

- **Add a model provider.** Write one adapter in `upshift/llm.py` that translates to the internal message
  format, add its variables to `.env.example`, and add a row to the provider table in the README.
- **Add or fix a playbook.** Playbooks in `playbooks/` are generated by research and reused. If one is wrong,
  fix the research or the prompt that produced it rather than hand-editing the JSON, and re-run with
  `--fresh-research`.
- **Change a pipeline phase.** Keep the run state in `upshift/state.py` up to date, so `upshift resume` can
  still continue a run that stopped in that phase.

## Pull requests

1. Open an issue first for anything bigger than a small fix, so we can agree on the approach.
2. Keep each PR to one change. Add or update tests for it.
3. Run `uv run pytest` and make sure it passes.
4. Update the README if you change a command, an option or an environment variable, and add a line to
   [CHANGELOG.md](CHANGELOG.md) under **Unreleased**.
5. Never commit keys or `.env` files. The pre-commit hook blocks them, so keep it installed.

Write commit messages as a short summary of what changed and why, for example
`Scan what ships: lockfile-aware installs and audit`.
