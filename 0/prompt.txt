## 1. What Upshift does

**Pitch** (README tagline: *"Dependabot opens the PR. Upshift makes it pass."*; the asset uses *"Your deps move. Your code keeps up."*):
Upshift is an agent that fixes the code a version change breaks. You give it a Python repo and a package to upgrade, or let it find the vulnerable ones. It researches the upgrade itself: changelog, release notes, the migration guide, and an API diff made by installing both versions. From that it writes a playbook where every rule cites its source. Then it bumps the dependency and fixes the code one root cause at a time. Finally it proves nothing new broke, against the test results it recorded before touching anything. It was built for #neatHack with neatlogs, Entire and cfo.ai, and you bring your own model key.

**Pipeline** (README "How a job runs"; `upshift/pipeline.py`):
1. **setup**: clone the repo, create a venv, install, resolve the target version from PyPI.
2. **baseline**: run the tests before changing anything (`entire graph verify --record-baseline`).
3. **bump**: rewrite the pins, install the new version, see what breaks.
4. **research**: docs, changelog, GitHub release notes and an API diff produce the cited playbook. This step is skipped for a security fix that breaks nothing.
5. **fix**: one root cause per round. Progress is committed and regressions are reverted. Uses the `entire graph search / impact / explain` tools.
6. **verify**: no new failures against the baseline and no old APIs left from the playbook. Security fixes run pip-audit again.
7. **report**: writes `UPSHIFT_REPORT.md` with the changes, verification and sources.

Every job is one neatlogs trace.

**Key features:**
- **Three commands:**
  - `bump`: upgrade a package.
  - `scan`: pip-audit/OSV, including transitive dependencies. It picks the smallest release that fixes every advisory, one job per package. A fix that breaks nothing is just a pin change with no model calls.
  - `python`: moves the Python pins in `.python-version`, the Dockerfile, GitHub Actions, tox and pyproject.
- `resume` continues a crashed run, and `--dry-run` makes no model calls.
- Playbooks are cached in `playbooks/` and reused (pydantic 1→2, jinja2 2.11→3.1, Python 3.10→3.12).
- A pre-commit secrets hook blocks committed keys.
- Every model client is wrapped with neatlogs tracing.
- **Roadmap:** "Third-party API drift comes next." The asset calls this `upshift watch`. It is not implemented in `cli.py`.

**Measured cost per job** (from `business/cfo-inputs.md`):
- requests security fix: $0
- jinja2 security fix: about $0.07
- pydantic 1→2: $0.33
- Python 3.10→3.12: about $0.51

## 2. Install and run commands (verbatim from README)

Requirements: Python 3.11+, uv, and the Entire CLI with its graph plugin (`entire plugin install graph`). Without Entire the agent still runs, but the graph tools report themselves unavailable. The CLI entrypoint is `upshift = "upshift.cli:main"`.

```bash
uv sync
python3 scripts/check_secrets.py --install   # pre-commit hook that blocks committed keys
cp .env.example .env                         # fill in your provider and key (git-ignored)

# no model calls: clone, baseline, research, bump, and show what breaks
uv run upshift bump --repo demo/shop_app --package pydantic --to 2 --dry-run

# the full agent
uv run upshift bump --repo demo/shop_app --package pydantic --to 2
uv run upshift scan --repo demo/shop_app                     # find known vulnerabilities and fix each one
uv run upshift python --repo demo/shop_app --to 3.12         # move to a newer Python and fix what breaks
uv run upshift resume &lt;run-id&gt;     # continue a crashed or killed run
```

Tests: `uv run pytest`.

Extra CLI flags: `--python`, `--fresh-research`, and `--from` (on the `python` command).

**Model providers** (set `UPSHIFT_PROVIDER` and `UPSHIFT_MODEL` in `.env` or your shell):

| `UPSHIFT_PROVIDER` | Needs | Notes |
|---|---|---|
| `anthropic` | `ANTHROPIC_API_KEY` | `UPSHIFT_MODEL` defaults to `claude-opus-5-5` |
| `azure-openai` | `AZURE_OPENAI_API_KEY`, `AZURE_OPENAI_ENDPOINT` | `OPENAI_API_VERSION=2024-10-21`; the model is the deployment name |
| `litellm` | `LITELLM_API_KEY` | Defaults to the neatHack proxy (https://neatlogs.com/hackathon/models); `LITELLM_BASE_URL` for your own proxy |
| `openai` | `OPENAI_API_KEY` | `OPENAI_BASE_URL` for OpenRouter, Groq, Together or a local server |
| `bedrock` | `UPSHIFT_AWS_PROFILE` | `UPSHIFT_AWS_REGION=us-west-2`; an explicit profile is required |

- The neatHack proxy models are `claude-opus-4.6`, `claude-sonnet-4.6`, `claude-haiku`, `nova-pro`, `nova-lite`, `nova-2-lite` and `nova-micro` (e.g. `REDACTED.6`).
- Optional: `NEATLOGS_API_KEY` (without it, spans are created but not exported) and `UPSHIFT_AGENT_VERSION=v0`.

**The demo app** (`demo/shop_app/`) is a small shop with orders, receipts and settings, deliberately pinned to old versions so each upgrade breaks something:
- **pydantic 1.10.13** in `shop/models.py` and `shop/orders.py`: `constr(regex=)`, `validator`, `root_validator`, `orm_mode`, `parse_obj`, `.dict()`. Upgrading to 2.14.0 makes the suite fail at import; after the fix all 16 tests pass and only models/orders changed.
- **jinja2 2.11.3** in `shop/receipts.py`: `Markup`, `escape`, `contextfilter`, `environmentfilter`. The 3.1.6 security fix covers 4 CVEs; Upshift moved the imports to markupsafe and switched to `pass_context`/`pass_environment`, and all 21 tests pass.
- **requests 2.31.0**: 3 CVEs, fixed by a pin change only, with no model calls.
- **Python 3.10** (`.python-version`, Dockerfile, CI): `shop/settings.py` uses `SafeConfigParser`, `distutils.strtobool` and `inspect.getargspec`. Moving to 3.12, Upshift produced `ConfigParser`, a local `strtobool` and `getfullargspec`; all 26 tests pass.
- **Untracked work in progress:** `shop/payments.py`, `tests/acme_sandbox.py`, `tests/conftest.py`, `tests/test_payments.py` and `scripts/traffic.py`, plus a modification to `shop/orders.py`. This is the API-drift demo. A fake "acme" payments API v1 sends `Deprecation`/`Sunset` headers ("Sat, 31 Oct 2026") and returns 410 after sunset, and the migration target is v2 `/v2/payments`. Traffic is logged to `logs/app.log` and traced in neatlogs. That feature isn't implemented yet.
